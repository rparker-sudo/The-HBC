# The HBC Volleyball Club website

Static website for The HBC Volleyball Club, a boys and girls volleyball club in Huntington Beach, CA.
Live at https://rparker-sudo.github.io/The-HBC/ (GitHub Pages, rebuilt on every push to this branch).

## Site structure (three wings)
A strip at the top of every page switches between the wings.

**Club wing** (root folder): black, white and silver, with pink touches for the girls program
- `index.html`: club home with the boys/girls program chooser
- `about.html`, `coaches.html` (all staff), `contact.html`
- Shared training for everyone: `clinics.html`, `private-training.html`, `summer-camp.html`

**Boys wing** (`boys/`): black, white and silver, no pink
- `boys/index.html`, `boys/teams.html` (teams & tryouts), `boys/coaches.html`

**Girls wing** (`girls/`): black and pink
- `girls/index.html`, `girls/teams.html` (teams & tryouts), `girls/coaches.html`

`teams.html` is kept only as a redirect for old links.

## Calendar
- Public pages: `calendar.html` (whole club, with Boys/Girls filter), `boys/calendar.html`, `girls/calendar.html`.
  Month and list views; each event opens a details box with time, location (linked to Google Maps) and notes.
- Data: `data/events.json`. Each event has `title`, `program` (`all`/`boys`/`girls`), `type`, `date`,
  optional `endDate`, `start`/`end` (24h), `location`, `notes`, and for weekly repeats `repeat: "weekly"`, `until`, `skip` (dates).
- Admin: `admin/index.html` (not linked from the site). Sign in with a fine-grained GitHub token that has
  Contents read/write on this repo; the page edits `data/events.json` through the GitHub API and commits it,
  and GitHub Pages republishes within a minute or two. Supports weekly repeats, skip dates, spreadsheet (CSV) import and a JSON backup.
- Admin tabs: **Calendar** (month view; click a practice to change *this practice only* or *this and all future practices*,
  with coach/court/team conflict checks), **Schedule Builder**, **All events** (table + CSV import), **Help**.

## Schedule builder
- Setup is saved to `data/scheduler.json`: season phases (labeled date ranges) and holidays, gyms (courts + available
  times, optionally per phase), coaches, teams (coaches, practices per week with optional per-phase numbers, length,
  full courts or a shared court, or a set schedule that isn't flexible), and special rules.
- Rules (Must or Prefer, optionally per phase): unavailable (coach/team/gym/court, days, times, optional date range),
  team uses a gym or court, practice days, time window, no back-to-back days, coach max per day, coach travel time
  between gyms, and two teams sharing one court.
- Court priority: `courtPriority` is one ranked list of individual courts across all gyms ({gym, court}); the generator
  fills higher-ranked courts first. A team can set `customPriority` with its own `courtPriority` list, where `off: true`
  means the team never uses that court. Gyms can name each court (`courtNames`).
- Generated times are written into each flexible team as `generatedSlots` (same shape as a set schedule's `fixedSlots`),
  so they can be edited in the team's listing; "Add to calendar" uses those rows. "Lock as set schedule" moves them into
  `fixedSlots` so regenerating won't move that team.
- `js/scheduler.js` is the engine: set schedules are placed first, then it tries many arrangements and keeps the one
  that places the most practices with the best rule score. Coaches are never double-booked and a court holds at most
  one full-court team or two shared-court teams. "Add to calendar" turns each phase's weekly pattern into weekly
  events (holidays and dated unavailability skipped) and replaces earlier generated practices from the chosen date on.
- The engine also runs in Node for testing: `const S = require("./js/scheduler.js")`.
- The admin commits to the branch GitHub Pages serves (set under Advanced settings on the admin page).
  Pull before making code changes so you don't overwrite calendar edits.

## Editing
Pages are generated by `tools/build.py`. Change the text there and run:

```sh
python3 tools/build.py
```

Styles live in `css/styles.css`. Each wing's colors come from the `.theme-club`, `.theme-boys` and `.theme-girls` blocks at the bottom of that file.
Behavior (mobile menu, contact form) lives in `js/main.js`. The contact form preselects the program from `?program=boys` or `?program=girls`.
